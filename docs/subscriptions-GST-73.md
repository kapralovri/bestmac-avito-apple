# GST-73 · Подписки «модель + моя цена»

Статус: **спроектировано и реализовано** (этот PR).

## Задача

Владелец хочет задать в боте конкретную конфигурацию и свою предельную цену,
после чего получать уведомление сразу, как только такой лот появится на Avito
дешевле этой цены.

Сегодня алерты приходят только по одному критерию — **выгодность относительно
рынка** (`MIN_MARGIN`, `MIN_NOTIFY_SCORE`). Это отвечает на вопрос «где рынок
ошибся», но не на вопрос «где то, что мне нужно, по моей цене». Лот за 45 000 ₽
при медиане 47 000 ₽ выгодным не считается и не придёт — хотя для владельца,
готового купить именно эту конфигурацию за 45 000 ₽, он ровно то, что нужно.

## Решение в одном абзаце

Бот ведёт файл подписок, сканер его читает на каждом прогоне intake. Если
карточка от расширения совпала с подпиской по конфигурации **и** цена не выше
заданной — уведомление уходит немедленно, минуя рыночные гейты. Гейт состояния
(стоп-слова) остаётся включённым: сломанный аппарат не нужен ни за какие деньги.

Код расширения не меняется: его четыре вкладки уже собирают все MacBook, iMac,
Mac mini и Mac Studio, а сопоставление с подписками делается на сервере.

## Модель данных

`public/data/subscriptions.json` — бот пишет, сканер читает (та же схема
владения, что у `watchlist.json`).

```json
{
  "a1b2c3d4": {
    "id": "a1b2c3d4",
    "chat_id": 123456789,
    "model": "MacBook Air 15 (2023, M2)",
    "label": "M2 8/256 ГБ",
    "match": {"family": "MacBook Air", "chip_gen": "M2", "chip_tier": "base",
              "screen": 15, "ram": 8, "ssd": 256},
    "max_price": 45000,
    "url": "https://www.avito.ru/...",
    "created_at": "2026-09-15T12:00:00",
    "hits": 0,
    "last_hit_at": null
  }
}
```

### Почему `match` — словарь, а не ключ-кортеж

Напрашивалось хранить `live_key(cfg)` — шестёрку
`(family, chip_gen, chip_tier, screen, ram, ssd)` — и сравнивать на равенство.
Не подходит: в каталоге парсера RAM и SSD есть **только у MacBook**. Записи
iMac, Mac mini и Mac Studio описаны как «модель + чип», без памяти и диска:

```
{'model': 'MacBook Air 13 (2020, M1)', 'processor': 'Apple M1', 'ram': 8, 'ssd': 256}
{'model': 'imac 24', 'processor': 'm1'}
```

Сравнение кортежей потребовало бы выдумать `ram`/`ssd` там, где их не знает сам
каталог, и подписка на iMac не совпала бы никогда. Поэтому `match` содержит
только те поля, которые реально известны, а сравнение игнорирует отсутствующие.
Подписка получается настолько точной, насколько позволяет каталог: для MacBook —
до гигабайта, для остальных — до чипа. Это же делает схему расширяемой: появится
в каталоге память для iMac — подписки станут точнее без изменения кода.

## Компоненты

### 1. `scripts/common/subscriptions.py` (новый)

Чистая логика, общая для бота и сканера — без сети и файлов в сигнатурах:

| Функция | Назначение |
|---|---|
| `load_subscriptions(path)` / `save_subscriptions(path, data)` | чтение и атомарная запись |
| `make_subscription(...)` | собрать запись с `id` и `created_at` |
| `subscription_matches(sub, cfg, price)` | совпала ли подписка с лотом |
| `find_matches(subs, cfg, price)` | все сработавшие подписки |
| `match_from_config(cfg)` | `MacConfig` → словарь `match` (пропуская неизвестное) |

Правило сопоставления: цена `<=` `max_price`, и каждое **заданное** поле `match`
равно одноимённому полю конфигурации лота. Пустой `match` не совпадает ни с чем —
страховка от подписки-ловушки, которая иначе слала бы вообще всё.

### 2. Бот (`scripts/negotiation-bot/bot.py`)

Переиспользует существующий визард `/модель` (семья → модель → конфигурация).
К экрану выбранной конфигурации добавляется кнопка **«🔔 Следить за этой
конфигурацией»**; бот спрашивает предельную цену, следующее число в чате
становится подпиской. Новый визард не пишется.

- `/подписки` — список активных с кнопками удаления;
- отмена ввода цены — кнопкой или командой, чтобы не залипнуть в режиме ожидания.

### 3. Сканер (`scripts/hot-deals-scanner/scanner_v2.py`)

В ветке `run_intake`, **до** гейтов рынка и маржи:

```
карточка → prefilter → classify → совпадение с подпиской?
                                    ├─ да  → deep_analyze → гейт состояния → алерт «🔔 По подписке»
                                    └─ нет → обычный путь (рынок → маржа → скоринг)
```

Сработавшая подписка уводит лот со стандартного пути (`continue`), чтобы один
лот не приходил двумя сообщениями. Рыночный контекст, если он известен,
печатается внутри карточки подписки — информация не теряется.

## Что осознанно не делается

- **Подписка не влияет на выкупную цену и скоринг.** Это отдельный канал
  уведомлений, а не новый источник истины о рынке.
- **Нет подписок на произвольный текст.** Только конфигурации из каталога
  парсера: иначе не с чем сопоставлять `classify`.
- **Нет расписаний и тихих часов у подписки.** Смысл в мгновенности; ночной
  шум ограничен тем, что подписка узкая по определению.
